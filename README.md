# 开放空间私服启动器

Windows 单机 / 局域网服务端管理启动器，支持本地 UID 登录、独立存档、公服账号数据采集与导入、房间和玩家管理。界面采用原创天空蓝/海洋青动漫海边插画、宽松按钮与独立采集页面，不嵌入游戏截图或玩家数据。

**启动器内置自动更新。** 启动时后台检查对应国服/国际服正式版，自动下载并验签小型核心更新包；游戏、服务、采集空闲后倒计时安全切换并重启。提供“检查更新、暂停自动、稍后”，不必每个日常版本手动重新下载便携包。

- **支持 Steam 版公服客户端**：可直接选择 Steam 游戏快捷方式（`.url`，指向 `steam://rungameid/...`）。这类客户端不在配置里固定游戏端口，因此改为按服务器地址采集，并按实际能解析出游戏协议的方向判定收发。
- **修复 VPN / 隧道网卡抓包为空**：隧道网卡把裸 IP 包记成以太网帧，导致 TShark 读不到 TCP、解包结果为 0。现已识别并修正链路类型，保留原始抓包并另存修正副本。
- **采集改为分段轮转**：PktMon 只在停止时才把缓冲写入磁盘。改为每 12 秒落盘一段，采集中就能看到实际进度，不再长时间显示「暂时无法判断」。
- **退出启动器会清理本次启动的服务**：管理员模式下关闭窗口不再残留 `Lolo.exe` / `room_gateway.py` 占用端口；游戏仍在运行时不会误停。
- 备份工具更新至 **1.0.9**：修复部分 Wi-Fi 原生帧误标以太网造成 0 TCP 流的问题。
- 公服采集页增加 **17 项项目清单**：展示已采集、空列表、尚未采集、未采集到及暂不可判断，并给出对应操作建议。

本版最重要的修复：**导入账号后私服无法进入（服务端报 `Mismatch type bool with value number`）**。导入器把 `isUnLock` 等布尔字段写成了数字 `1`，服务端反序列化失败导致 `player is nil`。现已按模型定义输出真正的 `true` / `false`。

本版相对 `v1.1.0` 的变化：

- **修复布尔字段被写成数字**，导入后私服可正常登录（`isUnLock`、`isLock` 等 10 个布尔字段）。

- 解码不完整的包默认拒绝并说明原因，确认后才允许导入，避免覆盖成空外观存档。

## 构建

Windows 上需要 .NET Framework 4.x，以及 Visual Studio 2022 的 C++ x64 构建工具：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_launcher.ps1
cmd /c build_sdk.cmd
```

`build_sdk.cmd` 默认使用 VS 2022 Community 的工具环境；其他安装版本请调整该脚本。
启动器核心脚本使用 Python 3.12；本地 UID 服务不需要在线代理或 `mitmproxy`。新的实验性 QuickSDK PC 适配需要 Frida 17.24.3；源码环境可执行 `python -m pip install -r requirements.txt`。其中 `mitmproxy` 用于旧重定向脚本和相关回归测试。备份工具使用独立 Python/Protobuf/Cramjam/TShark 环境，完整解压工具包后还需按采集说明准备运行依赖。旧 Release 便携包自带当时的运行时，但不含本次新增适配的全部依赖。

**组件包与源码（开发或自定义用）**


## 使用

### 本地 UID 登录（日常使用）

不需要官服账号，也不联网认证，直接在本机进游戏：

1. 「单机模式」填一个本地 UID，任意数字都行。
2. 点「更改目录」选中本地 PC 客户端目录。
3. 点「启动单机游戏」，首次会复制独立客户端副本，稍等片刻。
4. 游戏出现原渠道账号弹窗时**不用登录，直接关掉**，或点「进入游戏」即可进入本机服务。

游戏标题可保持原样，启动器不改系统代理。B 站 PC 版使用 PCGameSDK 本地适配；TapTap 下载的已验证 QuickSDK PC 包使用独立实验适配，不再盲目替换 PCGameSDK.dll。具体版本哈希、依赖与限制见 [TapTap 私服适配说明](docs/taptap-private.md)。仅含 TapTap DLL 的未知布局或不同版本不保证兼容。

### 公服账号采集（最新主干）

1. 点击左侧“公服采集”，进入独立页面。
2. 点击“开始采集”；PktMon 采集需要管理员权限。
3. 退出并重新打开自己的原版官方客户端，正常认证并进入场景，打开需要备份的角色、背包、装备、宠物、邮件、家园等界面。
4. 点击“结束采集”，等待解包；核对采集 UID 和已有存档冲突提示，再确认入库。
5. 本地 UID 与公服身份不是同一机制。采集时不要启动私服副本或转发工具；不需要向服主提供公服密码或 QQBot 保存的 token。

完整运行依赖、产物及排查见 [公服采集说明](docs/official-capture.md)。**本节功能已包含在 `v1.1.0` 便携版附件中。**

### 通用步骤

1. 在可写目录运行 `OverFieldLauncher.exe`，更改目录，选择兼容的本地客户端安装目录；B 站 PC 版及实验性 QuickSDK PC 适配的具体范围见对应说明，其他版本不保证兼容。
2. 服务端需自行从合法来源提供 `LoloServer`，包括 `Lolo.exe`、`config.json`、`data/`、`Resource/` 和数据库架构。仅玩局域网服务端时可将这些内容放入启动器旁的 `server-kit/`。
3. 不要将个人数据库当作公开模板。新建单机/局域网存档只复制数据库架构，不复制模板中的账号或进度；已有模式存档保持不变。个人进度必须由用户明确导入。公开服务模板仍应只含架构，且 `data/` 内不能夹带密钥或个人数据。
4. 填入自己的本地 UID，选择单机或局域网服务。首次准备会创建独立数据目录。
5. 如需恢复个人资料，使用“导入数据”选择自己的解码抓包 ZIP，确认预览后导入。服务会先停止，原数据库自动备份。

存档、导入报告、管理密钥和日志在 `profiles/solo` 或 `profiles/host`；运行状态在 `runtime/`。不要上传这些目录。关闭启动器不代表所有已启动服务已停止，请使用停止按钮管理服务。

## 局域网与安全

局域网 HTTP / UID 网关 / 日志端口为 19080 / 19100 / 19200。房间管理接口仅监听本机，并在首次运行时生成管理密钥。Windows 防火墙规则仅允许同一局域网；本项目为本地 UID 模式，不具备公网身份认证，不应暴露到互联网。每台电脑自行导入自己的资料，存档不会自动同步。

## 玩家备份工具与登录流程

`backup-tool/` 收录玩家数据备份工具源码及协议许可证，支持本人官服数据抓包、PCAP 解码和家园归档。便携运行时不进入源码仓库，完整 Windows 工具另作 Release 附件。源码版依赖设置、导入 ZIP 结构和隐私警告见 [备份工具说明](backup-tool/README.md)。

官服原账号登录与本地 UID 登录不是同一机制；数据不会凭 UID 自动获取。完整流程见 [登录与数据获取方法](docs/login-and-data.md)。

### 渠道服（非官方登录）

**渠道服太多了，这里只提供经验，具体情况具体解决。**

本人使用的是 **MuMu 模拟器渠道服**，数据保存是在模拟器上完成的：先正常登录自己的渠道账号 → 管理员身份开始抓包 → 在模拟器里重新登录并进场景 → 逐个打开角色、背包、宠物、邮件、家园等界面等加载 → 结束抓包并核对 `summary.json`。

和官服最大的区别是抓包对象变成了模拟器里的游戏进程，最容易卡住的是**端口**和**流量路径**（模拟器 NAT 模式下流量可能不经过宿主机网卡）。

其他渠道服（B 站、TapTap、应用宝、小米、华为等）的服务路径、账号体系和端口都不同，**请带自己的渠道、模拟器类型和具体现象去请教 AI**，不要照搬本篇步骤。

完整经验、差异对照和排查顺序见 [渠道服登录与数据保存经验](docs/channel-login.md)。
