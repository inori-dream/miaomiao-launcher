# 公服账号采集

公服采集页提供「公服启动器路径 / 开始采集 / 结束采集」。抓包确认就绪后会自动打开配置的公服启动器，使用自己的公服账号正常登录；结束后核对数据并确认写入本机账号库。

## 和私服启动的区别

| | 连接目标 | 登录方式 |
| --- | --- | --- |
| 单机 / 局域网 | 本机私服 | 本地 UID 回调 |
| **公服采集** | **官方服务器** | **你自己的渠道账号正常登录** |

公服采集**不会**把本地 UID 注入官方客户端，也不绕过官方认证。UID 在这里只是本地数据库的账号身份。

## 使用流程

1. 以管理员身份运行启动器（采集官方流量需要 PktMon，必须管理员）。
2. 选择单机或局域网模式，确认「启动设置」里的 UID（这个 UID 会在采集包缺少 UID 时用于建档）。
3. 在左侧「公服采集」页点击「选择启动器」，选原版公服启动器或游戏客户端 EXE；该设置保存在独立的 `officialLauncherPath`，不会更改私服的 `gameRoot`。
4. 点「开始采集」，等待「抓包已就绪，公服启动器已打开」。需要直接看到游戏界面时，请选择原版游戏的 `launcher.exe`；若选择平台主程序，它只负责打开平台，仍需从平台进入游戏。用**自己的渠道账号**正常登录并进入场景。
5. 逐项打开要保存的界面：角色、穿搭染色、背包、武器装备、任务、宠物、好友、邮件、抽卡记录、成就图鉴。分页内容逐页打开。
6. 进入自己的家园，等家具加载完整。
7. 回到启动器点「结束采集」。

启动器会自动停止抓包、转换 PCAP、解码，并生成 `account_玩家名_UID.zip`。随后弹出「保存采集账号 ZIP」对话框（默认桌面，可自选位置），成功保存后在资源管理器选中文件，交给用户。

**先交付 ZIP，再选择是否入库。** 取消入库或 UID 冲突不会删除已经保存的 ZIP。取消另存时内部原文件仍保留，可点击「保存账号 ZIP」再次另存；重新打开启动器后也可恢复上次有效产物。只有用户确认入库才会初始化/写入本机账号库。

交付的是标准 1.0.5 账号数据 ZIP，不包含额外的原始 `.etl` / `.pcapng` 抓包。它仍含个人账号资料，请只私下发给可信服主，不要公开。若没有获得有效的单账号数据，不会伪造空 ZIP。

公服路径不会回退到私服路径，空路径、`profiles` 私服副本、已替换本地 UID SDK 的客户端会被拒绝。公服启动使用可见的直接进程，不调用私服启动器或注入器，并移除 `LOLO_*` 环境变量。抓包初始化失败或超时不会打开公服；公服启动失败会发送停采信号并保留日志。已有私服服务应先停止，以免采集混入私服流量。

## UID 规则

- 采集包里有 UID → **用采集到的 UID** 建档并登录。
- 采集包没有 UID → **用你在启动器里填的 UID** 建档。
- 目标 UID **已有存档 → 判为冲突**，不写入，界面会显示已有账号的昵称与等级。

冲突时不会覆盖任何数据。需要覆盖请先自行备份该账号，或换一个 UID。

## 产物位置

```
profiles/<模式>/db/lolo.db          账号库（账号、存档、基础信息）
profiles/<模式>/accounts/<UID>/     原始响应与导入报告
runtime/capture-sessions/<时间>/    原始 ETL、PCAP、解码输出
runtime/capture.log                 采集日志
```

原始抓包含登录令牌与好友资料，只留在本机，不要外传。

## 依赖

需要 `backup-tool/`（已更新到 1.0.9，含 Wi-Fi 帧兼容修复）以及 TShark。免配置便携包自带 Python 运行时与 TShark；自行部署时设置 `OVERFIELD_TSHARK` 或把 TShark 放到 `backup-tool/tools/tshark/`。

检查环境：

```powershell
python official_capture.py status
```

返回 `ready: true` 表示可以采集；`problems` 会列出缺少的组件或权限。

## 采集项目清单与 Wi-Fi 修复

公服采集页显示 17 项清单：登录、主数据、角色外观、背包、武器、护甲、海报、宠物、家园家具、邮件、卡池、抽卡记录、成就、图鉴、探索、好友、档案/生活技能。每项显示响应数和未采集时的操作建议。

- **已采集**：确实收到成功解码的相应公服响应，不把客户端请求或错误响应算成功。
- **已收到（列表为空）**：服务器成功返回空列表，与“没有收到”不同。
- **尚未采集**：当前可读取快照中尚未看到对应数据；可按建议打开界面触发。
- **暂时无法判断**：ETL 仍在写入、系统暂不能读取快照等情况，不能据此认定数据缺失。
- **未采集到**：结束采集后，按完整解码 JSON 核对仍缺少该项。

前端每 2.5 秒读取最新清单。**采集过程中通常看不到逐项结果**：PktMon 通过 ETW 缓冲写入，数据先攒在缓冲区，缓冲区写满或结束采集时才落盘。所以采集中页面显示「暂时无法判断」并不代表没有数据，下方会同时显示 PktMon 实际记录的数据包数；**点「结束采集」后立即得到完整核对结果**。

1.0.9 会识别误标为以太网的原生 Wi-Fi 帧，只在验证了明文 LLC 头后修正链路类型和残留加密标记。修正文件另存为 `capture.wifi-fixed.pcapng`，原始 `capture.etl` 和 `capture.pcapng` 保留。旧 PCAP 也可用新工具重新解析，无须重抓。

上游 `MANIFEST.sha256` 的原始来源记录保留为 `UPSTREAM-MANIFEST.sha256`，启动器的 ReadyPath/StopFlag、UTF-8 和实时观察器适配见 `INTEGRATION.json`；上游文件清单不代表适配后的脚本仍逐字相同。

## 已知限制

- 只能保存客户端实际收到的数据，不是服务端全量导出。
- 必须管理员权限；普通权限会明确提示，不会静默失败。
- 采集期间不要同时开私服模式，避免客户端连到本机。
- 协议与端口按现有国服记录配置（TCP 11001–11004、21001、21002），渠道或版本变化时需要调整。
- 官方客户端版本兼容性未在本次改动中实测，不保证所有版本可用。
- **地图探索度与星云树**：抓包采集会记录各场景探索数据（含 `exploration.json`/`exploration.txt`）及星云树数据包并完整保存进账号 ZIP；但当前默认 `Lolo.exe` 服务端尚未实现星云树与大地图总探索百分比的持久化与下发，因此这两项目前可以采集保存、暂不支持导入私服恢复（地图内收集物、月亮与区域解锁可正常写入 `SceneMap`）。

## PktMon 状态与错误排查

PktMon 原生输出按 UTF-8 读取，不再依赖 PowerShell 5.1 宿主的 GBK 编码。否则中文“没有运行”可能被解码成乱码，导致安全检查误判为未知诊断会话。

繁体 Windows 返回的 `[封包監視器] 並未執行。` 表示抓包未运行。旧状态判定遗漏了方括号与“並未”，会误报“无法确认 PktMon 会话属于本备份工具”；现已兼容该状态，以及带方括号的简体中文和英文空闲提示。这类报错应修正状态识别，杀进程无法修复文字判定。每次采集开始前仍会检查并清理可确认归属的上一轮备份会话与筛选器。

修复保留会话归属保护：只有可确认属于备份工具的旧会话和筛选器才允许清理，未知或其他工具的会话不会被停止。若仍失败，请查看界面显示的具体首行错误以及本次采集目录的 `capture-worker.stderr.log`，不要盲目执行全局 stop/filter remove。

```powershell
python -m unittest tests.test_pktmon_encoding tests.test_official_launcher tests.test_official_import tests.test_launcher -v
```

`test_official_import` 使用合成数据覆盖：采集 UID 优先、缺失时回退登录 UID、显示 UID 优先于内部 ID、冲突拒绝写入、导入后其他账号不受影响、ZIP 路径安全。
