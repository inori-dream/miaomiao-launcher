# 自动更新 / Signed automatic launcher updates

## 用户使用

从 v1.4.0 开始，国服/国际服启动器默认在后台检查本项目的正式 GitHub Release，选择对应 CN/EN 小型核心更新包，验签和校验后下载到本安装的 `runtime/updates`。

底部提供“检查更新 / Check now”“暂停自动 / Pause auto”“稍后 / Later”。检查和下载不阻塞游戏/采集按钮。下载完后只有游戏、服务、采集及操作全部空闲并确认状态，才进入可推迟的倒计时，安全退出旧窗口、替换文件并重新启动。不会强行停止游戏或服务。

这里的“热更新”是自动获取并安全切换启动器文件，不是在运行中替换已加载的DLL。网络失败、签名错误或状态未知时继续使用原版，不强行应用。

## 首次引导版本

v1.3.0及更早版本没有更新模块，无法凭空下载新模块。首次需要升级到v1.4.0；之后日常版本由启动器获取小型更新包，不必每次重下整个便携包。现有本机安装可由维护者进行一次经校验的引导更新，仍须保留存档、配置和本地改动。

## 不会自动改的内容

- 玩家存档、profiles及其游戏副本；服务器私有资源/数据/配置、数据库和WAL/SHM。
- launcher.settings及运行中的采集文件/日志。
- 游戏本体、Python/TShark等运行时以及第三方安卓APK。

APK仍是独立第三方原包下载，不会被Windows更新器安装、执行或改签名。服务器资源、运行时或格式大迁移必须另行验证，不能靠通用核心更新包静默覆盖。

## 来源与完整性

更新仅读取 `inori-dream/miaomiao-launcher` 正式Release。必须存在 `launcher-update.json` 和 `launcher-update.sig`；清单的原始字节用专用RSA2048 PKCS#1 v1.5 SHA-256签名，客户端固定公开校验参数。仅GitHub HTTPS和受控资产重定向允许下载。

每个包和安装文件还校验大小及SHA-256。拒绝错误edition/版本、降级、重复JSON键/ZIP成员、大小写碰撞、路径越界、符号链接/重解析点、Windows保留名和超预算内容。清单缺失或验证失败不会退回任意附件/镜像下载。

哈希不是签名替代；私有签名密钥不存于仓库、便携包或APK，也不复用Git认证密钥。

## 应用、改动和失败恢复

`installation-manifest.json` 记录该版受管文件基线。检测到用户修改受管代码/文档时，暂停并保留修改，不把它当正常旧版本直接覆盖。配置与存档不属于受管文件。

应用助手再次验签/校验并等待旧窗口退出；检查活动任务；备份、原子替换和事务日志用于失败回滚。未知身份或状态不按空闲处理。不要手工把未验证的stage文件标成ready。

暂停自动允许已开始的下载完成，但停止后续自动检查/切换；稍后推迟切换，不删除下载。日志保存在本安装的更新目录，原始游戏/采集备份仍由用户保管。

## 维护者发布

每个后续正式版需要同时生成并上传对应核心ZIP、签名清单和签名；仅改GitHub版本标题或上传普通便携ZIP不会成为有效自动更新。

构建命令（开发环境需Node.js；终端用户不需安装Node）：

```powershell
python build_update_assets.py --version 1.4.0 --source . --templates <已审核的便携包目录> --out <资产目录> --node <现有node.exe> --signing-key <仓库外专用私钥.pem>
```

保管及备份专用签名私钥，限制读取权限，不打包或提交。生成器先校验受管路径，生成新安装基线并校验真实签名；再上传资产，全部校验成功后才公开Release。若需要轮换公钥，须由现有受信密钥授权的版本引入，不能把任意远程公钥当可信。

自动测试不代表每个系统/网络/权限环境都验证；更新不可用时保留当前程序，不自动降级安全策略。
